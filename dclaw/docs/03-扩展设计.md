# 03-扩展设计

## 1. 目标

这份文档收拢 MVP 之后的扩展方向，避免后续开发时把中后期能力混进主链路。

## 2. 长会话能力

### 2.1 Compact

作用：

- 自动压缩旧上下文
- 控制长会话 token 增长
- 保持 query engine 在长任务中可持续运行

详细参考：

- [architecture.md](./architecture.md)
- [phases.md](./phases.md)

## 3. 执行组织能力

### 3.1 Plan / Task / Todo

作用：

- 在复杂任务中显式管理执行步骤
- 支持 plan mode
- 支持任务状态跟踪

这是 Claude Code 成熟度很重要的一层，不应省略。

## 4. 长期记忆能力

### 4.1 Memory

作用：

- 用文件系统保存长期记忆
- 用 `MEMORY.md` 做索引入口
- 通过 relevance recall 做按需召回

详细参考：

- [memory-spec.md](./memory-spec.md)

## 5. 多代理与隔离执行

### 5.1 Agent / Coordinator / Worktree

作用：

- 支持任务委派
- 支持多 worker 协作
- 支持 worktree 隔离执行

详细参考：

- [agent-spec.md](./agent-spec.md)

## 6. 扩展生态

### 6.1 MCP

作用：

- 接入外部 tools 和 resources

### 6.2 Skills

作用：

- 封装可复用 prompt / workflow

### 6.3 Plugins

作用：

- 提供可安装扩展
- 可挂载 skills、commands、hooks、MCP

### 6.4 Remote / Structured IO

作用：

- 支持 SDK / headless 机器可读输出
- 支持 remote session 和 bridge

详细参考：

- [skill-spec.md](./skill-spec.md)
- [mcp-plugin-spec.md](./mcp-plugin-spec.md)

## 7. 后置场景能力

### 7.1 Coding 场景增强

这是后续场景层，而不是核心主架构的一部分。

可包含：

- repo/workspace 感知
- 开发任务工作流增强
- 代码场景下的 prompt/tool 组合优化

## 8. 实施顺序

建议顺序：

1. compact
2. plan / task / todo
3. memory
4. 多代理 / worktree
5. MCP
6. skills
7. plugins
8. remote / structured IO
9. coding 场景增强

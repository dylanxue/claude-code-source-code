# 01-总体方案

## 1. 项目定位

`dclaw` 是一个终端优先的通用 agent 项目，目标是严格参考 Claude Code 已体现出的通用能力边界来实现。

这里的“通用能力”主要包括：

- CLI / interactive / headless 双入口
- query engine 与消息循环
- system prompt 装配
- `CLAUDE.md` 指令系统
- tool 协议与工具注册
- permission mode 与 hooks
- session / history / resume
- compact / autocompact
- plan / task / todo
- memory 与 recall
- subagent / coordinator / worktree
- MCP / skills / plugins / remote bridge

`coding` 相关能力不是核心定义，而是后置场景增强。

## 2. 设计原则

1. 严格对齐 Claude Code 的通用能力（源码在本项目下，跟dclaw目录平级的目录就是claude code的源码)，不额外“加戏”。
2. 通用能力优先，不把 coding 逻辑写死进核心模块。
3. 会话、任务、memory、代理都要以长期可恢复为目标。
4. 先搭主链路，再补成熟度增强件。

## 3. 总体结构

建议分层如下：

- `cli/`：运行入口与命令解析
- `core/`：query engine、消息循环、streaming、budget/abort
- `llm/`：模型适配层
- `prompt/`：system prompt 与 `CLAUDE.md` 指令装配
- `tools/`：tool 协议、registry、builtin tools、MCP tool 包装
- `permissions/`：权限模式与工具执行控制
- `hooks/`：session hooks / function hooks
- `session/`：transcript、resume、history
- `compact/`：上下文压缩
- `tasks/`：plan / task / todo
- `memory/`：长期记忆、recall、team sync
- `agent/`：subagent、coordinator、worktree
- `mcp/` / `skills/` / `plugins/` / `remote/`：扩展与远程能力

## 4. 核心主流程

```text
用户输入
  -> CLI
  -> QueryEngine
  -> Prompt 装配
  -> 模型调用
  -> assistant 响应
  -> 如果包含 tool_use
     -> registry 查找工具
     -> 权限判定
     -> 执行工具
     -> 生成 tool_result
     -> 回填消息继续循环
  -> 最终输出
  -> 持久化 session
```

### 4.1 Plan Mode 基本规则

`plan mode` 在 `dclaw` 中不是单纯的工具只读开关，而是一个会影响会话行为的显式阶段，设计上对齐 Claude Code 当前源码表现：

- 模型可以建议进入 `plan mode`
- 模型可以发起进入 `plan mode` 的请求
- 真正切换当前 session 到 `plan mode` 必须经过用户确认
- 用户也可以通过 `/plan` 等显式命令直接进入
- 退出 `plan mode` 并开始实施时，也应提供明确的用户确认点

进入 `plan mode` 后，系统不仅要限制变更型工具，还要让模型进入“探索 -> 澄清 -> 出方案 -> 等批准”的工作节奏：

- 优先读代码、查模式、识别风险
- 可以提出澄清问题
- 输出结构化 plan / todo / current step
- 在退出 `plan mode` 前不直接开始文件改动

这意味着阶段 9 的目标不是做一个“查看计划列表”的命令，而是把 planning 变成可观测、可切换、可恢复的会话状态。

按 Claude Code 当前源码口径，当前已落地到代码的最小对齐包括：

- 已接入模型侧 `EnterPlanMode` / `ExitPlanMode`，且真正切换 session 状态仍要求用户确认
- 已接入 `TaskCreate / TaskList / TaskGet / TaskUpdate`，并让模型看到长版 task tool prompt，而不是只有短 description
- 已接入最小 runtime task reminder：当已有 task board 且最近几轮未继续使用 `TaskCreate / TaskUpdate` 时，会临时注入 Claude Code 风格的 task-tool reminder
- 已接入最小 attachment-style plan-mode reminder：`plan_mode`、`plan_mode_exit`、`plan_mode_reentry`
- 已接入 compact 后第一轮的强制 full `plan_mode` reminder，避免 compact 后丢失 planning 语义

当前这些 runtime reminder 仍以临时 `<system-reminder>` user meta message 近似，但仅作为当轮 runtime 注入，不单独持久化到 transcript；transcript 继续以 `EnterPlanMode / ExitPlanMode` 工具事件和 plan 真值为主。后续再继续补齐更完整的结构化 runtime 语义。
